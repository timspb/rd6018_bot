# V3 charge screen specification

Экран получает только `RuntimeUISnapshot` и `ChargeJournal`. Одна журнальная
запись отображается одной строкой; форматирование не находится в ChargeEngine.

Первая строка панели содержит название выбранной АКБ: слева
`RD6018 · <название АКБ> · <режим регулятора>`, справа — текущая стадия
(`MAIN`, `MIX`, `FLOAT` и т.п.). Для ручного запуска справа показывается режим
и фактическая стадия (`РУЧНОЙ · MAIN` или `РУЧНОЙ · MIX`); параметры АКБ
остаются отдельной строкой ниже.
В активной панели температура БП показывается всегда отдельным значением
`🌡 БП`; служебная подпись `Управляемая ручная сессия` пользователю не
показывается — вместо неё выводятся фактическая стадия и evidence перехода.

Для Telegram доступен переключаемый presentation-режим `OPERATOR_PANEL_STYLE`.
Значение `text` оставляет обычное сообщение, значение `dark_card` отображает
те же данные в чёрной PNG-карточке под обычным графиком. Композиция обновляется через
редактирование существующего сообщения; состояние и кнопки не меняют runtime-
контракт.

Обязательные блоки: стадия/phase, профиль и chemistry, elapsed time этапа и
всего заряда, target V/I, active OVP/OCP limits, recipe, `waiting_for`,
transition evidence, Vmax/Imin, delta и hold.

PREP показывает старт/параметры/переход; MAIN — CC/CV и evidence; RECOVERY —
попытку, budget, причину и результат; MIX CC — Vmax/ΔV/hold; MIX CV —
Imin/ΔI/hold/containment; SAFE_WAIT — причину и следующий шаг; DONE — итог.

UI не создаёт ChargeIntent, не меняет state и не имеет доступа к RD, HA,
Output, controller или FSM.
