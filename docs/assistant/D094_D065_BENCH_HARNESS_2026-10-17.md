# D094 — D065 offline acceptance harness (2026-10-17)

## Scope and current status

This change adds a reproducible offline executor and isolated ESP-node model at
`tools/node104_d094_d065_bench_harness.py`. It cannot connect to Home Assistant
or ESPHome, has no direct edge-button interface, and accepts only its in-process
`OfflineNode` gateway. `DisabledLiveGateway` always raises. The generic injected
gateway is the single action boundary for a future separately reviewed and
legitimate approved action channel. This release deliberately rejects every
non-simulator implementation.

**Physical command tests: NOT RUN.** The prior Safety Lease Renew/Disarm
invocation was explicitly blocked by the execution environment. This run does
not retry it or use an equivalent route. The block is an execution-environment
limitation, not a firmware result or missing operator permission. The live
service, node104 and ESPHome were not accessed or changed. No deployment, push,
or merge was performed.

## Contract-derived expected state

Use a fresh evidence capture immediately before and after each operator action.
The acknowledgement/callback that a command was requested or accepted is not
proof that the ESPHome lambda passed its guards. In physical acceptance, require
independent fresh HA and native ESP observations. Native output R18 and measured
voltage/current must be typed `SensorState`; same-object `NumberState` values are
programmable setpoints and do not count as output measurements. Do not infer
physical Output from an HA switch, stale callback, or NumberState. Confirm native
source callback age and independent HA `last_reported` age (the established
collector requires <=8 s native sensor age); confirm R18 OFF and actual V/I=0
before and after every OFF-only action.

| Action | Required before state | Proven after state | Generation |
|---|---|---|---|
| Managed Renew | Fresh direct Modbus/control and Output readback; R18 OFF for initial arm; managed=false, autonomous=false, trip=false, boot quarantine=false; TTL exactly 900 s | armed=true, trip=false, quarantine=false, conflict=false, positive remaining lease; R18 remains OFF and measured V/I remain zero | Exactly +1 |
| Managed Disarm | Fresh direct control and Output R18 OFF; autonomous=false; no conflicting authority | armed=false, remaining=0, managed authority released, autonomous=false, trip=false; R18 still OFF and measured V/I zero | Unchanged by the current firmware lambda |
| Enter Autonomous | Fresh direct control and Output R18 OFF; managed=false, autonomous=false, trip=false, quarantine=false | autonomous=true, armed=false, no conflict; R18 still OFF and measured V/I zero | Exactly +1 |
| Exit Autonomous | Fresh direct control and Output R18 OFF; autonomous=true, managed=false, trip=false, quarantine=false | autonomous=false, armed=false, remaining=0; managed=false (idle, no old session resume); R18 still OFF and measured V/I zero | Exactly +1 |

Fresh readback after action is essential. Renew increments generation only after
all local guards pass. Disarm does not increment generation in the present YAML;
its proof is the readback showing managed lease unarmed, remaining zero and
autonomous false. Autonomous transitions increment generation on accepted local
state changes. Any absent/failed command acknowledgement, unchanged/incorrect
generation, stale readback, or state mismatch is a failed/indeterminate test,
never a pass. Preserve the observed state and invoke only the existing supervised
safe-OFF procedure if physical containment is needed.

The software OFF-only smoke invariant additionally holds setpoint <=15.5 V,
unchanged passive deadman TTL=900 s and renewal cadence=300 s, single actuator
owner with handoff lock, no accidental ON, fresh independent HA/native R18 and
actual V/I evidence, and fail-closed cancellation/timeout. The separate
`safe_off_helper` accepts only the existing verified-OFF port interface; it is
not called against a real node by this harness or this sprint.

## Operator-controlled supervised physical matrix (not run here)

An authorized operator at the existing node104 test stand controls every live
action, supervises the stand and keeps the emergency disconnect available. Keep
setpoint at or below 15.5 V. Keep the firmware's passive 900 s deadman and 300 s
renewal unchanged. This accepted authorization does not add a battery wrapping,
insulation or load-replacement requirement. For each OFF-only step, record exact
firmware identity/digest, action request and acknowledgement separately, fresh
before/after HA and native typed SensorState evidence, generation, armed,
remaining, autonomous, trip/quarantine/conflict, R18, measured V/I, setpoint,
TTL and timestamps. Do not count a simulator result as physical acceptance.

1. Capture the independent verified-OFF baseline and confirm all preconditions.
2. On verified OFF, perform one managed Renew, then prove armed and positive
   remaining with generation +1. Perform managed Disarm and prove unarmed,
   zero remaining, autonomous false and unchanged generation.
3. On verified OFF and no managed owner, Enter Autonomous and prove mode plus
   generation +1. Exit and prove autonomous false, managed lease still
   disarmed, and generation +1. These transitions never energize Output.
4. Separately test AUTONOMOUS energized beyond 900 s only under the authorized
   supervised stand conditions with the operator controlling the output and
   emergency disconnect. Prove the unchanged 900 s managed deadman does not
   silently revoke explicit autonomous operation; record the energized test as
   its own acceptance item, not as an OFF-only smoke test.
5. Separately test ESP-only reboot while Output is ON in AUTONOMOUS and verify
   the persisted non-conflicting autonomous authority behavior. Separately test
   managed/default/conflicting reboot quarantine and verified Output OFF. These
   are distinct gates and must not be inferred from enter/exit success.
6. Any timeout, cancellation, stale source, missing/failed acknowledgement,
   failed invariant, unexpected ON or uncertain state stops the matrix. Use the
   established supervised safe-OFF procedure and preserve raw evidence; do not
   retry an ambiguous action automatically.

Other D064 raw-protection/thermal injection, persistence-fault, exact firmware
digest and signed exact-source acceptance gates remain separate and open.

## Offline evidence

The fake node tests model positive transitions and failure cases including
missing/failed ack, stale SensorState, NumberState confusion, generation
progression, Renew without confirmed armed state, Disarm without zero remaining,
Autonomous entry with a managed lease, accidental Output ON, >15.5 V, boot
quarantine/trip and simulator-only rollback. No live application process is
started. This is executable contract evidence only, not physical acceptance.
