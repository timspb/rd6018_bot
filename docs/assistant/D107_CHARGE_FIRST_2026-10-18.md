## Приоритеты разработки, конкретный результат вместо новых release-gates

1. **MAIN Current Guard (EFB/Ca/Ca):** начальная уставка `min(Iрецепт, 0.1 C, 12 A)`; через каждые 30 минут доказанного MAIN Output ON предлагать уменьшение до `min(Iпредыдущая, Iфакт + 1 A, I0)`; повышение по обычному ходу MAIN запрещено. Возврат к I0 после промежуточной десульфатации — только при подтверждённом Output OFF и прямых Iset/OCP readbacks. Довести единого владельца сессии и команд до физического выполнения **без второго контроллера**; сначала разбирать реальные логи и ограниченную физическую калибровку.
2. **MIX EFB/Ca/Ca:** проверить поведение CC/CV, Delta и двухчасовую выдержку, температурное ограничение и условия адаптивного уменьшения лимита тока. Уже существующий `mix_current_containment.py` сохранить как модуль; требуемую headroom/шумовую калибровку получать из RD/аккумулятора, а не назначать числом из головы. Агм не менять.
3. **Релаксация АКБ:** использовать пассивные записи `voltage_relaxation.db` по подтверждённому Output OFF для анализа скорости падения напряжения (5–15 и 15–60 минут); корреляция по реальным сеансам, температуре и ёмкости — **диагностика**, не автоматический алгоритм увеличения напряжения.
4. **Модульность и подтверждение на железе:** стратегия ≠ исполнитель ≠ ESP-защита ≠ Telegram/HA. Прямой ESPHome — приоритетный источник физических register/readback/lease данных; HA — вторичный маршрут. Испытательная уставка напряжения не выше 15.5 В, оператор наблюдает стенд; deadman 900 c неизменен.

**Важно про напряжение MIX:** в текущем каноне generic EFB AUTO/Recovery/Conditioning имеет потолок 16.5 В. Ранее обсуждавшиеся 17–17.3 В нельзя незаметно включить в AUTO: это отдельное решение по экспериментальному протоколу после доказательных измерений. AGM исключён из пересмотра.

## D107 прикладное исправление

Исправлен `runtime/charge/strategy/main_guard_shadow.py`: устаревший proposal из прошлой EFB/Ca/Ca MAIN-сессии не возвращается на другом химическом профиле, сессии, батарее, при другом этапе, неизвестном Output или отсутствии принятой identity. Pending остаётся привязан к исходной сессии и **не расширяет ранее ограниченную власть по току**. После таймаута pending и при ошибке current-sample наружу выдаётся `None`; строка `fresh="false"` не считается свежим boolean доказательством. Это чистая логика; исполнитель тока/OCP не вызывался. Алгоритмы AGM, напряжения MIX, ESPHome, device I/O и production не изменялись.

**Открытый прикладной участок:** принятое удостоверение сессии для MAIN Guard shadow ещё не публикуется production owner. Нужна жёсткая привязка к фактической атомарной `charge_session.json`, затем последовательные write/readback в том же `ExecutionPort` и запись фактических токов/ошибок — не новый процесс обновления.
