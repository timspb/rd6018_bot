# D108 — MAIN Current Guard: реальная сессия

Дата: 2026-10-18. Source-only, без изменений node104/ESPHome/RD6018.

## Найденная причина

D073 пытался получить идентификатор сессии, АКБ и исходный ток из трех полей, которые production никогда не устанавливал. Поэтому guard не наблюдал реальные сессии MAIN.

## Исправление

Добавлен модуль runtime/charge/strategy/main_guard_admission.py — только чтение внутри существующего общего ExecutionPort lock. Он сверяет реальную атомарно записанную charge_session.json, идентификаторы сессии/АКБ, начальное время, профиль EFB/Ca/Ca, емкость, этап MAIN, актуальность записи и штатный рецепт select_main_target. Дополнительно требует свежий Output R18, ток, Iset и OCP, причем реальный Iset должен уже соответствовать допустимому исходному рецепту не более 0.1C и 12A.

Никакой новый контроллер, файл сессии или отдельный исполнитель не создаются. Отсутствие подтверждения сбрасывает доказательство непрерывного ON и запрещает новое предложение. Обновлены MainGuardShadow и уже существующая data_logger внутри единого владельца.

Во время активной MAIN файл сессии может иметь поле output_intent=off — это правило терминального завершения, а не измерение текущего Output; применяется только физический регистр R18.

Расчет после подтвержденных 1800 с формирует предложение по текущему току +1 A с монотонным ограничением. Управляющие Iset/OCP записи не включены; журнал Guard отдельно не пишется. Это не физическая приемка и не разрешение на Output ON. Следующий этап — совместная атомарная запись сессии и guard, аппаратная транзакция при уже активном зарядном процессе и readback на стенде, без параллельного исполнителя.

AGM не изменен. MIX и пределы ESP не менялись. Лимит физического стенда 15.5 В, deadman 900 с.
