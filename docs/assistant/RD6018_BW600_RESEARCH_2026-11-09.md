# RD6018 / BW600-FX — исследование электронного разрядника
Дата: 2026-11-09. Только документирование публичных источников; без физического оборудования и без запуска команд.

## Задача
Выбрать ≥5 А электронную нагрузку ATORCH BW600-FX-150W с локальным программным CC/CP/режимным управлением и телеметрией для связки RD6018 charge → rest → discharge → result, желательно через HA102 и существующий Recipe Studio. Пользователь заинтересован и в замене Tuya-модуля на ESPHome. Точный SKU пользователя: https://www.ozon.ru/product/bw600-fx-150w-elektronnaya-nagruzka-dlya-testirovaniya-akkumulyatorov-1-200-v-do-30-a-wifi-tuya-4859945506/

## Проверено по документации производителя, обзорам и кодовым проектам

1. **Функции BW600**: 1–200 В, 150 Вт, до 30 А при сохранении ограничения мощности, CC/CP и дополнительные CV/CR/test-режимы, отдельное питание DC 12 В 1 А, 4-wire sense, температура и ёмкость. Руководство указывает Wi-Fi/Tuya и USB/HID PC. Устройство только электронной нагрузки; зарядный коммутатор — отдельный модуль. https://manuals.plus/m/dcb614f6ba219a12e1665334be45b8923902366085acc539575666b0b682de37 ; https://manuals.plus/ae/1005010258084821

2. **Локальный Wi-Fi без облака во время эксплуатации уже реализован:** https://github.com/sq6emm/bw600 (README, исследованный BW600-DK firmware V2.0.5). Python 3.10+, Tkinter/CLI, `tinytuya`, первоначальная связка с Smart Life/Tuya + local key через Tuya developer; после получения local key сеть локальная. DP 101 U, 102 I, 103 P, 104 load on/off, 105 mAh, 106 Wh, 108 mode, 109 set value, 110 time, 112 discharge cutoff, 113/114/118 temperatures, **122 refresh 1 s vs idle 60 s**. Старт ~0.5–1.5 s, останов ~0.5 s на авторском приборе; репорт и повтор подтверждения OFF присутствуют в авторском коде, но не являются сертифицированной защитой. По Wi-Fi не все USB-функции доступны; OCP/OPP, калибровки, cycle count, factory reset и др. USB-only. Контроль реального физического OFF проверяется отдельно.

3. **USB HID полный локальный контроль:** https://github.com/PeeJay/Atorch_BW600 — PC HID VID:PID 0483:5750, 64 bytes, OUT 55 05 01 CMD ... EE FF, IN AA 05 01 CMD ... EE FF. Команды 03/05 polling, 21 setpoint, 25 on/off, 47 CC, 48 CV, 49 CR, 4A CP. Telemetry U/I/P/Wh/mAh/temp. Независимое расширенное исследование https://github.com/sq6emm/bw600 включает режимы 0–9, отсечку, защиту, настройки, reverse firmware; проверено на BW600-DK firmware V2.0.5. **Совместимость с заказанным BW600-FX-150W и VID/PID нужно проверять на самом экземпляре.** Не запускать произвольные firmware bootloader commands, особенно `55 05 09 02`.

4. **Отдельный UI и драйвер:** https://github.com/Battrix/Atorch_BW600 — лабораторный web GUI/USB, Wi-Fi/BT и ESP32-C3 модификация в roadmap; README говорит USB BW600-DK tested, другие интерфейсы WIP. Использовать как справочник/сравнение, не объявлять WiFi/ESP функциональность завершённой.

5. **ESPHome имеет непосредственный прецедент:** https://github.com/1RandomDev/atorch-bw150-esphome — BW150/DL24: исходный Tuya CB2S заменяется на ESP8266-12F или совместимое решение, UART Tuya MCU, DP101–121, HA/MQTT. `CB2S` = BK7231N (https://developer.tuya.com/en/docs/iot/cb2s-module-datasheet?id=Kamwxuk0z7j9x). На BW600 модель Wi-Fi-субмодуля НЕ установлена, а доказанной готовой прошивки ESPHome BW600-FX не найдено. Возможны ESPHome/LibreTiny/OpenBeken после точной идентификации SoC и проверки UART/пинов; ESP32-C3 — альтернатива с аппаратной переделкой, не готовый drop-in.

6. **Разделение электроники:** обзор c вскрытием https://www.kirich.blog/obzory/izmeritelnoe/1280-atorch-bw600-prodolzhenie-lineyki-nagruzok-dl24mp.html подтверждает отдельный WiFi-субмодуль в соответствующей комплектации, основной контроллер, USB, fan, heat, измерения. Описаны перегрев и риск неисправности вентилятора на ранней плате, проблемы теплового интерфейса и токовые всплески с дополнительными power-модулями. В комментарии 2026 автор отмечает последующие изменения плат/радиаторов. Для 5 A при 12–15 V нагрузка около 60–75 W, но длительный тепловой тест конкретного экземпляра обязателен.

7. **Плата коммутации заряд/разряд:** https://www.kirich.blog/en/reviews/technical-reviews/1303-atorch-bw600-load-switching-board.html — обзор предупреждает о недостатках ранних версий и снятии исследованной платы с производства. Не приобретать/не применять автоматически до проверки ревизии, полярности, двустороннего разрыва, номиналов, interlock и отказных состояний. Одновременная зарядка и разряд, как минимум, требуют физически гарантируемого взаимоисключения; WiFi/HA статус не является interlock.

8. **Фирменное ПО/прошивки**: ATORCH через http://en.atorch.cn/NewsDetail.aspx?ID=92 (BW600), ID=96 (BW600-DK); копии firmware V2.0.3/V2.0.5 и vendor links описаны в репозитории sq6emm. Для USB мостика в PeeJay упоминается JieLi AC632N/AC6321A. Не перепутать **основной MCU/USB** с WiFi субмодулем. Обновление firmware приборa и перепрошивка радио — два независимых риска. Не делать без резервного образа, способа восстановления и точного чипа.

9. **Форумы:** 4PDA E-test обсуждает совместимость BW150/BW600 и проблемы фирменного PC ПО: https://4pda.to/forum/index.php?showtopic=1062412&st=120 ; Kirich обсуждает аппаратные ревизии и тепловые проблемы. У отдельного ATORCH GR2P найдены CB2S примеры на Elektroda, но переносить тип SoC с GR2P на BW600 нельзя.

## Технический вывод и порядок
- **Рекомендуемый путь для RD6018:** при получении BW600-FX WiFi сначала не вскрывать и не шить. Проверить точную прошивку, hardware revision, USB VID/PID и опубликованные DP, штатную отсечку и 5-A long-run cooling. Затем протестировать локальный `tinytuya` read-only/status и USB read-only на отдельном тестовом стенде, сравнить с HA LocalTuya. Выбрать один авторитетный actuator transport для каждого устройства; HA допустим в роли адаптера, но не второго владельца управления.
- **Recipe Studio** позже расширить отдельным `DISCHARGE` исполнителем, его step-spec, U/I cutoff/temperature, записью Ah/Wh U(t), rest and measurement; штатный RD6018 charger controller должен остаться своим единственным владельцем. Никаких релейных аппаратных переключений без подтверждённого interlock.
- **ESPHome** только как второй шаг исследований: найти физическую маркировку Wi-Fi-модуля на конкретном экземпляре, сделать фото/проверить 3.3V UART, пассивно снять обмен `55 AA 03 ...`, сохранить прошивку; затем пробовать на запасном модуле или после подтверждения rollback. Из имеющихся источников нельзя достоверно назвать чип установленного BW600-FX.
- **Не смешивать семантику:** название FX в карточке Ozon ≠ доказанная идентичность тестового BW600-DK. 5-A пригодность по паспортной мощности ≠ подтверждение непрерывной 14-часовой работы. Cloudless operation после initial Tuya pairing не означает отсутствие зависимости при первичной выдаче local key. 1-s WiFi refresh зависит от DP122/соединения.

## Следующее исследование при получении устройства
Считать в read-only: маркировку model/version, USB descriptors and VID/PID, обнаружение локального WiFi и полный DP discovery, сравнение штатного экрана и телеметрии, тест local key без интернета после provisioning. Затем короткие выключенные тесты и этапные 5-A прогоны с температурными наблюдениями и физической независимой отсечкой. На устройство/зарядку команды не посылались.
