## Discovered defect and repair

The observer ran with an empty capability set while the protected quarantine journal was owned by rd6018:rd6018 and mode 0600. It therefore could not read the journal. The old snapshot code silently omitted guard state, and the event policy interpreted missing state as not-quarantined, producing a false charger.guard_recovered event.

Repair:
- systemd now grants only CAP_DAC_READ_SEARCH (AmbientCapabilities and CapabilityBoundingSet); no write-bypass capability is granted.
- An unreadable/missing quarantine journal now yields explicit guard_state=unknown, never ok.
- Guard policy is tri-state: unknown emits one warning and never clears an active quarantine; recovery is emitted only on an explicit readable ok state.
- Snapshot carries the incident timestamp/ID for identity.
- Existing already-queued critical event for the same fault code and incident start suppresses a duplicate on observer reconciliation.
- New regression tests cover unknown guard state, no false recovery, and no duplicate alert for an already queued incident.
